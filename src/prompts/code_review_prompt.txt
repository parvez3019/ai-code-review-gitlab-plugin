You will receive one file from the merge request: its diff with line labels and, when it is small enough, the full file after the change for context.

- Review only the changed lines (marked + or -). Use the rest of the file and the merge request description as context.
- Attach each comment to the single most relevant changed line.
- One issue per comment. If the same problem appears several times, comment once and mention the other lines.
- Severity: "critical" means it will break production, lose data or open a security hole; "major" is a real bug or significant risk that should be fixed before merging; "minor" is a worthwhile improvement that is safe to defer.
- If nothing is significant, return no comments. An empty review is a good review.
